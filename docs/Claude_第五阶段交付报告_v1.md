## 1. 怎么做到一次做完的：庭院引擎

12 个传统没有各写一套游戏，而是先做了一个共用的“庭院引擎”（`threshold/core/courtyard/`）：

| 部分 | 作用 |
| :--- | :--- |
| `engine.js` | 规则：干活得资源 → 资源只用来照顾动物或招待来客；功课只记录。存档、离线补偿、平台同步、休息日 |
| `ui.js` | 界面：顶栏、底栏、各种面板、朗读、录音播放、合成钟磬声 |
| `kit.js` | 场景工具：天空与真实月相、山、树、人、狗猫牛鸽子、落叶堆、雨雪 |
| `play.html` | 统一入口，只加载白名单里的包 |

每个传统只写三个文件：`pack.js`（平台信息、选项、须知、节历、录音权利）、`content.js`（经文，逐行对齐原文、转写、译文）、`game.js`（文案、功课、场景画法）。

功课有六种通用形式：分步礼仪、供奉、诵读、计数（念珠 / 转经轮 / 念珠绳）、静坐计时、知识卡片。照护有两种：照顾动物（狗、猫、牛、鸽子）和招待来客（锡克教公共厨房、新教食物站）。

## 2. 每个传统的分寸

| 传统 | 特别处理 |
| :--- | :--- |
| 伊斯兰教 | 只做知识与文化：不模拟礼拜，礼拜动作只写在卡片里；《古兰经》不用机器朗读也不配录音；不画任何人物 |
| 犹太教 | 只做知识与文化；神名写作 ה׳、转写 Adonai；安息日（周五日落到周六入夜，按耶路撒冷估算）不能干活、不能买卖 |
| 锡克教 | 经典《古鲁·格兰特·萨希卜》不可点击；经文不用机器朗读；做出的饭只能招待来客 |
| 天主教、东正教、新教 | 不模拟弥撒、圣餐、洗礼等圣事；不画耶稣、圣母、圣人像 |
| 印度教 | 神像只作远景；牛伤好后留在牛棚，不送养；伽耶特利注明部分传统需入门后念 |
| 神道 | 不画神体；香油钱不用游戏资源；不卖御守、不做付费神签 |
| 道教 | 和佛教、祭祖分开；不做算命、求签、画符 |
| 藏传 | 转经、绕寺一律顺时针；不画活佛与上师像 |
| 印度新乘 | 不画安贝德卡尔和佛陀像；讲历史，不评价其他宗教 |

## 3. 节历

节历引擎新增四种算法，十二个包的节日都能自动推算：

- 西方复活节和东正教复活节（Pascha），以及圣灰礼仪日、圣枝主日、受难日、升天节、五旬节。
- 伊斯兰历：按乌姆古拉历推算，一律标“估算”。
- 希伯来历：犹太新年、赎罪日、住棚节、光明节、普珥节（闰年在第二亚达月）、逾越节等。
- 每年固定的日期。

各包使用的日期来源：

- 印度教、锡克教、印度新乘：2026–2027 年的日期取自印度邮政等公开假期表。
- 藏历新年和萨嘎达瓦：按公开的藏历日历。
- 日本、神道、天主教的固定节日：按公历。

## 6. 诚实说明：哪些还不能算“真的对”

- 12 个新版本的经文、转写、译文、礼仪说明都是 AI 起草，`reviewStatus` 全是 `draft`。`node tools/release-check.mjs` 现在列出 94 个阻塞项，全部要由对应传统的顾问和母语者签字才能消掉。
- 新版本的界面只有简体中文和 English。繁体只覆盖平台页面，游戏内部没有做繁体。
- 藏文、古木基文、阿拉伯文、希伯来文依赖设备字体或谷歌字体。字体没加载时，藏文的叠写可能显示不正确，需要真机检查。
- 节日日期里，伊斯兰历、藏历每月的日子、部分 2027 年的印度节日标了“估算”。
- 场景是简笔画风格，比汉传和泰国两个手工版本粗糙。
