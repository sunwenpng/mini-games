# 非寺院型传统纸面推演：锡克教 · 谒师所（Gurdwara）

版本：v1.0  
日期：2026-11-09  
作者：Claude  
对应任务卡：P3-2（第一批方案第 6 节）  
配套代码：`threshold/traditions/sikhism.gurdwara/pack.js`（状态 research，平台不开放入口）

> 标注：**【事实】**有出处或常识可查；**【推断】**由事实推出；**【待验证】**必须由锡克教顾问确认。

---

## 0. 结论

1. **现有接口能描述锡克教谒师所，不需要改平台核心。** 包的元数据（选项、须知、规则、实践能力、节历、声音权利链）都能装下；平台注册表、筹备页、深链接、审核门照常工作。测试 `每个传统和版本都有双语名称…` 和 `包的选项都有文案…` 已覆盖这个包。
2. **推演发现三个缺口，已经用“包级字段”补上，没动平台代码：**
   - 经典的处置方式：新增 `rules.contentHandling`，表示“经典只能在合适的阅读情境出现”；
   - 头部覆盖等进入要求：新增 `rules.headCovering`；
   - 以服务为主的资源循环：`practices[].kind = 'service'`，产出的是“供出的餐数”，不是货币。
3. **真正的阻塞仍是人，不是代码。** 没有锡克教顾问和一间愿意合作的谒师所之前，不应该做任何可玩内容。

---

## 1. 为什么选锡克教做推演

- 汉传、泰国上座部都是“寺院 + 僧团 + 个人修行”。如果引擎只在佛教上试过，很可能悄悄变成“佛教引擎”。
- 谒师所的核心是 **Seva（无私服务）** 和 **Langar（公共厨房）**：任何人不分宗教、种姓、性别，坐在地上同排吃饭（Pangat）。【事实】这和“个人修行 + 功德”的结构完全不同。
- 锡克教没有僧侣阶层，经典《古鲁·格兰特·萨希卜》（Guru Granth Sahib）被当作在世的上师对待。【事实】这对“内容能不能当道具”提出了最严格的要求。

## 2. 接口逐项映射

| 平台接口 | 汉传 / 泰国的用法 | 锡克教谒师所的用法 | 是否需要改接口 |
| :--- | :--- | :--- | :--- |
| `status` | live / preview | research（不开放） | 否 |
| `options.ui` | zh-CN / th / en | pa（ਪੰਜਾਬੀ）、en、hi，全部 off | 否；新增 `pa` 语言条目，`script: 'Guru'` |
| `options.content` | lzh / pi-Thai | `pa-Guru`：古木基文书写，语言混合多种中古印度语言 | 否；`script` 与 `contentLocale` 本来就分开 |
| `options.voice` | 机器朗读 / 参考 / 自有 | 只允许经授权的 kirtan 录音（自有），不提供机器朗读 | 否 |
| `notice`（进入前须知） | 脱鞋、脚不朝佛像 | 包头、脱鞋、洗手、不带烟酒 | 否 |
| `practices[].kind` | practice / reading / offering | **service** 为主：Langar 帮厨、Pangat 同排用餐 | 否；service 原本就在能力表里 |
| 资源循环 | 扫院子得米 → 照顾动物 | 帮厨 → 供出的餐数（只计数，不能花） | 否 |
| `calendar` | 农历 / 泰国官方日期 | Gurpurab 日期有 Nanakshahi 与 Bikrami 两种历法之争【事实】 | 否；用 `fixed` 日期表，由顾问提供 |
| `rules.depictions` | 佛像不可点击 | 经典不可移动、不可点击；十位上师的画像需顾问决定 | 否 |
| `rules.contentHandling` | 无 | `scripture-requires-reading-context` | **新增包级字段**（平台暂不读取，作为人工审核项） |
| `rules.headCovering` | 无 | true | **新增包级字段** |

## 3. 不做什么（写进包规则，作为顾问审核清单）

- 不模拟 Ardas（祈祷）、不模拟 Amrit Sanchar（入教仪式）。
- 经典不出现在任何可点击、可拖动、可收集的对象里；不做“翻页阅读”玩法，除非顾问同意并规定阅读情境。
- 不出售、不奖励 Karah Prashad（供食）或任何与经典相关的物品。
- 不把 Seva 做成计分或排行；“供出的餐数”只是记录。
- 全包无广告（`rules.ads: false`），不只是神圣空间无广告。

## 4. 若将来制作，可玩部分的样子（只作推演）

- **空间**：谒师所外的鞋架与洗手处 → 大殿（只做导览，不做礼拜）→ Langar 厨房 → 同排用餐的大厅。
- **服务循环**：揉面、烙 roti、搅 dal、洗盘子、给来客盛饭。来客里有附近的工人、学生、旅行者，不分身份。
- **声音**：大殿里经授权的 kirtan；厨房的环境声。
- **节律**：Gurpurab 日 Langar 规模更大；日期表由顾问提供并写明采用哪种历法。

## 5. 上线前必须完成（同筹备页五项）

1. 锡克教顾问（至少一位来自合作谒师所的委员会成员）。
2. 旁遮普语、英语、印地语母语审校。
3. 经典文本的出处、许可与“阅读情境”规定；若不展示经文原文，则只做知识说明。
4. 经授权的 kirtan 录音与完整权利链。
5. 古木基文排版测试（字体、连写、换行）。

## 6. 对平台的后续建议

- 当第二个包也需要 `contentHandling` 时，再把它升级为平台读取的字段（例如在来源页和诵读器里拦截），避免现在过度设计。
- `rules.headCovering` 这类进入要求，长期可以统一成 `entryRequirements: ['shoes-off', 'head-covered', …]`，由平台在“进入前须知”里渲染图标。
